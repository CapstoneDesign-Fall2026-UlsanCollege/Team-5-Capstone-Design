# Demo Runbook

Prepared 2026-11-14. Candidate route, not a successful rehearsal receipt.

## Before starting

Confirm the [freeze decision](FREEZE_DECISION.md), exact build, mode, disposable accounts and seeded subject. Keep private auth steps off screen. Open the [matrix](MVP_VERIFICATION_MATRIX.md) and relevant sanitized receipts. Do not show browser tabs, account emails or recovery links in captures.

## Ordered route

1. State the environment and scope: live Supabase or Local Preview; name unverified criteria.
2. Sign in privately, then show the student view. Checkpoint: intended session/account, no credential display.
3. Create one task with subject and deadline. Checkpoint: one row with matching values.
4. Try a blank title. Checkpoint: rejected, no extra row.
5. Reload. Checkpoint: same task ID and data; use sanitized service evidence to support cloud claims.
6. Show completion and deadline display if tested. Do not equate a countdown with notifications.
7. Present the independent two-account receipt. If missing, state Not run; UI-only separation is not RLS proof.
8. Close with known defects, accepted exclusions and next action. AI quizzes/recovery are optional and must retain their limitations.

## Recovery

- Network/auth failure: stop the live claim, record the symptom and use a clearly announced historical receipt walkthrough.
- Local fallback: announce local-only storage before showing it; isolate browser data. Never label it cloud persistence or secure account isolation.
- Missing evidence: show the explicit gap, not an invented screenshot or prefilled Pass.
- Unexpected destructive behavior: stop and preserve sanitized observations; do not modify production configuration during the demo.

Rehearsal date/operator/build, checkpoints, deviations and actual result remain **Not run**. Link the completed rehearsal receipt in the [evidence register](EVIDENCE_REGISTER.md).
