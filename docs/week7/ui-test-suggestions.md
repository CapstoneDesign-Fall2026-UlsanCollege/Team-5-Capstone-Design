# UI Test  for Smart Study Companion

## Objective
This test suggestion focuses on validating the user interface quality of the Smart Study Companion before the midterm presentation. The goal is to confirm that the app is clear, usable, consistent, and ready to demonstrate in a live session.

## Recommended UI Test Checklist

| Test Area | What to Check | Suggested Result |
|---|---|---|
| App launch | Main dashboard loads correctly and navigation is visible | Clean layout, no broken elements |
| Subject flow | User can create/select subject without confusion | Clear labels, logical flow |
| Task creation | Add task form is easy to understand and complete | Fields are readable and consistent |
| Study plan | Completed task status is easy to recognize | Clear status indicators |
| Quiz flow | Quiz questions and answer options are readable | Good spacing and visible selection states |
| Result view | Quiz result is clearly displayed after submission | Score + feedback are easy to read |
| Persistence | Refresh keeps relevant data visible | No major UI loss after reload |
| Theme consistency | Dark mode and main screens follow a consistent visual style | Colors and spacing are aligned |

## Suggested UI Test Flow
1. Open the app and verify the dashboard layout.
2. Create or select a subject.
3. Add a new study task with deadline.
4. Open the Study Plan and confirm completion state is readable.
5. Open the quiz section and check question display.
6. Submit answers and confirm the result screen is clear.
7. Refresh the page and verify the state remains consistent.
8. Check dark mode for readability and visual consistency.

## Pass Criteria for Presentation
The UI is considered ready for presentation when:
- all main screens are visible and readable,
- core actions are easy to complete,
- quiz and task flows are logically structured,
- theme inconsistency is fixed or clearly reported,
- final result is documented with screenshots and test notes.

## Suggested Final Note
Before the midterm presentation, the team should be clear about UI clarity, workflow consistency, and honest reporting of any unresolved issues. The application should be demonstrated as a working student workflow, not only as a visual prototype. See you in Midterm Persentation.
