## 1. Overview

The Sprint 2 review showed that the project has reached a functional milestone. The main student workflow is working, but there are still opportunities to improve the product quality. These suggestions focus on refining the user experience, improving the visual design, and strengthening the project before the next sprint.

---

## 2. Key Suggestions

### 2.1 Improve the Visual Theme Consistency
The most noticeable issue in Sprint 2 was the inconsistency in the color theme and visual styling. This should be fixed as a priority because it directly affects the perception of the application.

Suggested actions:
- Standardize the color palette across all pages.
- Review button styles, cards, text contrast, and background colors.
- Ensure the same design system is used consistently for all modules.

### 2.2 Refine the Frontend CSS
The UI needs additional CSS cleanup to improve the overall presentation and ensure better readability.

Suggested actions:
- Review spacing and alignment across the interface.
- Fix inconsistent typography.
- Make components more visually balanced and easier to understand.

### 2.3 Run Another Full End-to-End Validation
After visual fixes are completed, the full flow should be tested again to ensure that core functionality remains stable.

Suggested actions:
- Re-check subject creation
- Re-check task creation and completion
- Re-check quiz flow
- Confirm persistence after refresh

### 2.4 Document Issues Clearly
Any design and quality issues should be recorded in a formal tracking document or GitHub issue so they can be resolved and monitored properly.

Suggested actions:
- Create a GitHub issue for the theme inconsistency.
- List the exact UI areas that need correction.
- Assign owners and deadlines.

### 2.5 Use a Fresh Tester for Final Review
It is useful to ask a teammate who is not familiar with the implementation to test the app from a new user perspective.

This can help reveal problems that the original developer may overlook.

---

## 3. Additional Recommendations for Future Sprints

- Keep the feature set focused and avoid adding too many changes at once.
- Test each feature after major UI changes.
- Prioritize usability and visual polish at the same time as functionality.
- Keep communication within the team clear and consistent.
- Review the project at the end of each sprint with both technical and user-focused criteria.

---

## 4. Conclusion

Sprint 2 was successful in terms of functionality, but there is still room to improve the product’s appearance and consistency. The suggested actions above will help the team strengthen the project and prepare it for a higher-quality future release.

The most important improvements are related to visual theme consistency, CSS refinement, and verified re-testing after fixes. If these tasks are addressed properly, the project will be more professional, more user-friendly, and more ready for final evaluation.
